# Grow Your Garden — Chromebook prototype

A React/Vite fantasy garden with a parent-owned Supabase account and cloud-saved garden state.

## Run locally
1. Install Node.js 20+.
2. Run `npm install`.
3. Create a Supabase project. In the SQL Editor, run `supabase.sql`.
4. Copy `.env.example` to `.env` and fill in the project URL and **publishable/anon** key (never use a service-role key in a browser).
5. Run `npm run dev`, open the URL shown in Chrome.
6. Create a parent account. Confirm the email if your Supabase authentication settings require it.

## Deploy
Deploy to Netlify, Vercel, or another static hosting provider. Set the two VITE_ environment variables in the host dashboard. Build command: `npm run build`; output directory: `dist`. Set the production site URL in Supabase Authentication URL Configuration. Chrome on Chromebook can install the site from the browser's app menu if install criteria are met. This is an early prototype; manifest icons, offline support, and polished installation behavior remain to be added.

## Important privacy and safety notes
- Parent-managed account only; do not ask the child to enter her full name, weight, height, or sensitive medical information.
- The separate parent PIN is **prototype UI gating only**, stored in memory and lost on refresh; it is **not secure parental authentication**. Use a distinct parent identity/role and server-enforced authorization before deploying for unsupervised child use.
- Habit entries are stored in the cloud under the authenticated parent account with row-level security.
- No calorie deficit or weight loss score is included. Individual dietary targets should come from a pediatric clinician.
- Supabase hosting/privacy settings and consent obligations should be reviewed before use by a child. The prototype has not undergone security/privacy testing.
- Seed stars reward daily visits, not calorie restriction or weight change. Flowers rest after inactivity and are never removed.

## Prototype limitations
No password reset UI, parent/child separation, robust offline sync, automated tests, or fully built character quests yet. The app needs a production security/privacy pass before real-world deployment.

## Deploy on Netlify (recommended hosting)
1. Create a private GitHub repository and upload the contents of the `grow-your-garden` folder to its root. **Do not upload your `.env` file.**
2. In Netlify, select **Add new project → Import an existing project**, connect GitHub, and select the repository.
3. Netlify reads `netlify.toml`: build command `npm run build`, publish directory `dist`, Node 22, and a fallback for client-side routes.
4. In **Project configuration → Environment variables**, add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` from your Supabase project. Use only the public/anon key, never the service-role key.
5. In Supabase, run `supabase.sql` and set **Authentication → URL Configuration → Site URL** to `https://YOUR-SITE.netlify.app`. Add the same URL (and any custom domain) as an allowed redirect URL.
6. Trigger **Deploy site** or **Retry deploy** after setting environment variables. Visit the Netlify URL to test parent sign-in and cloud persistence.
7. Optional: configure a custom domain in Netlify. Keep HTTPS enabled.

**Not production-ready for independent child use:** The prototype's PIN is stored only in memory and does not securely separate child and parent access. Before allowing unsupervised use, implement server-enforced parent authorization and child-safe account/session handling, review child privacy obligations, and test account recovery. The app does not yet support offline usage or a complete installable PWA experience.


## Parent-only nutrition journal (October 2026 update)

The parent dashboard includes a clinician-reported 1,779 kcal/day reference, editable by the parent, plus a manual food log (calories, protein, carbohydrates and fat). Entries save within the existing Supabase `gardens.state` JSON field, so **no additional SQL migration is required**. The child garden has no calorie display or calorie-based rewards. This is a reference, not a prescribed deficit calculated by the app.

**Security limitation:** The parent PIN in this prototype is held in browser memory and is not a security boundary. A child using the signed-in browser could access the parent screen. Do not enter sensitive personal health information or use independently until a real parent authentication/authorization system is added.

**Deployment:** Commit the updated files to the GitHub repository connected to Netlify. Netlify should rebuild automatically. Confirm `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are configured. The `dist` directory is generated by `npm run build`; do not drag-and-drop the source ZIP as a manual deploy.
